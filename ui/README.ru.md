# Нативный масштаб интерфейса

Встраивание: скомпилировать ui.cpp в x86 DLL и вызвать InstallUiScaleHooks(GetModuleHandleW(nullptr)) до возобновления главного потока игры. UiScaleHookStatus() возвращает краткий статус. Переменная MW_MODERN_UI_SCALE задаёт число от 1.0 до 4.0; отсутствие значения и 1.0 оставляют штатный масштаб.

Масштаб меняет логическую область интерфейса, сохраняя физический render target. Размеры берутся из текущего renderer штатными функциями, поэтому новая величина разрешения из Video учитывается после пересоздания renderer. Функция ConfigureUI получает логическую ширину; её штатный код обновляет камеры и расположение меню. Границы мыши и нормализация координат выбора объектов используют ту же логическую область. Шрифты, панели, кнопки, инвентарь и курсор увеличиваются согласованно.

В меню Video текущий пункт и проверка «это уже выбранное разрешение» сравниваются с физическим backbuffer. Штатные поля WorldController +0x78/+0x7C при масштабировании содержат логические размеры, поэтому два соответствующих участка перенаправлены на штатные getters renderer. Например, при backbuffer 2880×1800 и масштабе 2.0 выделяется 2880×1800, а 1440×900 остаётся отдельным выбираемым разрешением. Сами логические поля, расположение UI и границы мыши при этих сравнениях не изменяются.

При выборе масштаба, который оставил бы меньше 640×480 логических пикселей, применяется ближайший меньший допустимый масштаб. Например, 2.0 при 1280×720 ограничивается до 1.5; при 2880×1800 масштаб 2.0 даёт 1440×900 логических пикселей.

После фактического применения рядом с MW_MODERN_LOG создаётся ui-scale.log с физическим разрешением, логической областью и эффективным масштабом. Это позволяет отличить успешную установку перехватов от фактического вызова движка.

## Полученные адреса

Исследован локальный Steam Morrowind.exe 1.6.1820, SHA-256 EAC72E1B3524EE0012D080D3C2E2E00E401464E41EE54F9AFD6AAAADF2C221F5. Адреса ниже — VA при штатной базе 0x400000; код использует RVA относительно фактического HMODULE.

| Узел | Адрес | Проверенная роль |
| --- | --- | --- |
| ConfigureUI | 0x40F2A0 | __thiscall(WorldController*, int width), RET 4 |
| Вызов при запуске | 0x40E55E | E8 3D 0D 00 00 |
| Вызов при смене Video mode | 0x429B10 | E8 8B 57 FE FF |
| Mouse bounds | 0x408740 | __thiscall(MouseController*, left, top, right, bottom), RET 16 |
| Последующая установка bounds при Video mode | 0x429B30 | E8 0B EC FD FF |
| Получение renderer width | 0x6AC030 | Читает backbufferInfo[0] через renderer+0x544 |
| Получение renderer height | 0x6AC040 | Читает backbufferInfo[1] через renderer+0x544 |
| Нормализация экранной точки | 0x6F5150 | Делит x/y на размеры viewport |
| Блок получения размеров для нормализации | 0x6F5157 | 14 байт заменяются чтением логических размеров |
| Глобальный WorldController* | 0x7C67DC | Ссылка подтверждена кодом пути Video mode |
| Физический размер для выделения текущего Video mode | 0x63759D | 11 байт заменены CALL + NOP; ECX=physical height, EDX=physical width, EAX=WorldController |
| Проверка уже выбранного Video mode | 0x638464 | Пять байт заменены JMP; сравнение использует getters renderer |
| Возврат без смены разрешения | 0x638480 | Исходный эпилог при совпадении физических W/H |
| Применение нового разрешения | 0x638488 | Исходный путь с восстановленными EAX=WorldController и ECX=selected height |

Поля WorldController: renderer +0x30, MouseController* +0x50, viewWidth +0x78, viewHeight +0x7C. Перед изменением проверяются PE32/x86, базовый адрес образа и сигнатуры всех мест вмешательства, вызываемых функций и используемых полей. Неизвестная версия или чужой патч отклоняются до записи. Ошибка записи вызывает откат набора.

## Проверки

Запуск test-build.cmd собирает x86 MSVC /O2 /W4 и исполняет ui-test.exe на частном отображении реального EXE через SEC_IMAGE. Оригинальный файл не изменяется и игра не запускается.

Проверены масштабы 1.25, 1.5, 2.0 на разрешениях 1920×1080, 2880×1800, 1280×720 и 2560×1440. Исполняются реальные перехваченные CALL запуска и смены разрешения, штатные getters renderer, штатная функция границ мыши и штатный код нормализации raycast после замены размеров. Только сложная ConfigureUI в тестовом образе заменяется заглушкой для проверки переданного аргумента. Проверяются углы, центр, изменение разрешения и ограничение минимального логического размера. Отдельно проверены отказ на изменённой сигнатуре, коротком образе и некорректном числовом масштабе.

Все 12 сочетаний прошли; сборка завершилась без предупреждений. В игре подтверждались смены физических разрешений с согласованным изменением логического UI. В v10 живой снимок подтвердил высоту списка Controls, геометрию строки режимов Video и её мировые координаты; пользователь подтвердил работу Controls. Audio оставалась пустой, а видимые кнопки режимов не срабатывали. Сборка v11 содержит отдельное исправление окончательной высоты Audio и исправление выбора кнопок. Их интерактивная проверка ещё ожидается: приватный тест подтверждает вызовы и координаты, но не создаёт полный UI движка.

Регрессия физических разрешений также исполняет оба настоящих новых перехвата на частном образе EXE. Для выделения проверяется точный контракт регистров ECX/EDX/EAX. Для сравнения воспроизводится штатный стек после sscanf: selected width находится в ESP+0x18, selected height — в ESP+0x1C; переходы удаляют 16 байт аргументов, как исходный код. Проверяются отсутствие пересоздания при выборе текущего физического размера, принятие логического размера как отдельного разрешения, независимые изменения ширины и высоты, сохранность логических размеров и правильные регистры ветки применения. Все 12 сочетаний разрешения и масштаба прошли со сборкой MSVC x86 `/W4 /WX`.

Адаптивное расположение вкладок, закреплённые действия и разделение ролей шрифта описаны в [Options](options-layout.ru.md). Семантика трёх режимов окна и масштабирования изображения — в [описании экрана](../display/README.ru.md).

## Первичные источники

- [MGE XE mwbridge.cpp](https://github.com/Hrnchamd/MGE-XE/blob/master/src/mge/mwbridge.cpp): сопоставлены механизмы логического viewport, штатной конфигурации UI, границ мыши и raycast.
- [MGE XE mwinitpatch.cpp](https://github.com/Hrnchamd/MGE-XE/blob/master/src/mge/mwinitpatch.cpp): подтверждён момент изменения UI при запуске.
- [MWSE TES3WorldController.h](https://raw.githubusercontent.com/MWSE/MWSE/master/MWSE/TES3WorldController.h): сопоставлены поля WorldController.

Реализация написана отдельно: готовые классы, патчеры и исходный код MGE XE/MWSE в модуль не включены. Машинные сигнатуры и соглашения вызовов подтверждены локальным дизассемблированием. Проект может распространять этот модуль под своей лицензией.
