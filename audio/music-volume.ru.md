# Master и музыкальная громкость

Музыка использует отдельный DirectShow IBasicAudio, а штатный callback
Master обновляет DirectSound-звуки. В v13 добавлен узкий перехват музыкального
пути: Master учитывается при запуске музыки, изменении её громкости, fade
и перемещении ползунка Master. Пользователь подтвердил на слух, что в v13
музыка затихает при Master=0. Это игровое подтверждение дополняет
изолированные native/ABI-тесты.

Общий SFX-путь остаётся нерешённым: пользователь перестал слышать воду через
10–15 секунд, но шаги остаются при Master=0, в том числе после Footsteps=0.
Актуальная SFX-трасса показывает нулевые настройки и передаваемые значения,
но не идентифицирует слышимый звук и не объясняет его дальнейший путь.
Формулы эффектов, громкость Windows и исходные настройки Music музыкальным
исправлением не изменяются; оно не объявляется универсальным Master/SFX fix.

## Расчёт и сохранение настроек

Мод получает уже рассчитанное движком музыкальное значение, выраженное в
сотых долях dB. Master=250 передаёт его без изменения; Master=0 явно
передаёт −10000. При промежуточном Master к исходному значению добавляется
2000 × log10(Master / 250), результат округляется и ограничивается
диапазоном −10000..0. Для Master=125 добавляется примерно −602, то есть
−6,02 dB. Диапазон и единицы, включая значение −10000 для тишины, описаны в
[Microsoft IBasicAudio::put_Volume](https://learn.microsoft.com/en-us/windows/win32/api/control/nf-control-ibasicaudio-put_volume).

SoundManager+0x294 хранит исходное значение Music, а +0x29C — громкость,
которую native get_Volume сохранил перед использованием графа. Мод не
записывает ни одно из этих полей и не передаёт произведение ползунков
штатному setter. Поэтому Music не затирается при перемещении Master.

Для уже играющей музыки кэшируется последнее немасштабированное native
значение dB. Это позволяет после Master=0 вернуть текущую ступень fade,
а не начальную громкость трека. Кэш связан с текущими manager/IBasicAudio
и поколением жизненного цикла. Четыре native участка восстановления перед
Release всегда инвалидируют кэш, в том числе при quit World; исходное
сохранённое dB на этих участках передаётся точно, без Master.

При отсутствии кэша callback Master вызывает штатный Music setter с тем же
исходным Music, только если значение конечно и находится в диапазоне 0..1.
При недоступном World, установленном quit flag или несоответствии текущего
графа обычные музыкальные вызовы проходят без дополнительного масштабирования.

## Перехватываемые native участки

| Участок | Адреса исходного EXE |
| --- | --- |
| Семь активных put_Volume, включая mute и fade | 0x403707, 0x403715, 0x4037A7, 0x4037BD, 0x403A95, 0x403AAF, 0x403BC3 |
| Четыре restore перед Release: только passthrough и инвалидация | 0x401D58, 0x40332E, 0x40348E, 0x403C37 |
| Master callback после исходного обновления эффектов | CALL 0x5A1C9E → 0x5A1E10 |
| Запуск без fade, перед native Run | CALL 0x410FE8 → 0x4034C0 |

Последний участок нужен отдельно: World::PlayMusic(false) вызывает
LoadGraph, QI/get_Volume и сразу Run, не проходя через активные put_Volume.
Перед таким Run кэш инициализируется фактическим сохранённым значением
+0x29C. При Master=250 дополнительного put_Volume нет: начальная громкость
графа остаётся ровно штатной. При Master<250 уровень применяется до Run.
Таким образом покрывается и холодный запуск с сохранённым Master=0.

На обычном запуске World публикуется до создания SoundManager; World+0x34
публикуется после его конструктора и до LoadGraph. Внутри LoadGraph native
get_Volume и установка flags&1 предшествуют Run. Это проверено по исходному
EXE, а не предполагается по названию функций.

Всего устанавливаются 13 перехватов после проверки PE/x86, всех исходных
инструкций, setter, callback, LoadGraph/get_Volume, Run и GUID IBasicAudio.
При ошибке защиты или instruction-cache flush восстанавливаются исходные
инструкции и права всех четырёх страниц. Несовпадающий EXE отклоняется до
первого изменения. Установка выполняется до возобновления главного потока.

Обычные COM-перехваты сохраняют настоящий результат и LastError. Master
возвращает результат исходного callback; дополнительное обновление музыки
его не заменяет. Pre-Run сохраняет входные GPR/EFLAGS/LastError и передаёт
управление исходному Run. Нет фонового потока, atexit или работы из DllMain.
Диагностический callback root записывает MusicMaster/MusicPreRun в game.log.

## Воспроизведение проверки

Из каталога audio:

~~~cmd
music-volume-test-build.cmd "D:\Steam\steamapps\common\Morrowind\Morrowind.exe"
~~~

Путь к EXE можно передать явно, в том числе из отдельного checkout.
Без аргумента используется Morrowind.exe на два каталога выше скрипта.
Нужны Visual Studio 2022 Community и x86 toolchain. Тест не запускает игру,
окно или аудиоустройство. Он отображает исходный EXE в отдельный SEC_IMAGE
своего процесса и исполняет оригинальные инструкции в приватной копии.
Абсолютные ссылки и импорты перенесены только в этой копии; файлы, создание
COM-графа и аудиодрайвер заменены recording doubles.

Результат /W4 /WX:

- 18 native-проверок исходного setter и fade;
- 42 проверки restore, Stop, Release, quit и повторного использования адреса;
- 615 отклонений повреждённых signature/ABI/IID-байтов;
- 117 проверок реально изменённых участков, включая аргументы COM,
  HRESULT, LastError, stack, GPR и x87; pre-Run также проверяет входные
  EAX/ECX/EDX/EFLAGS;
- 20 nonfade-проверок: отрицательный контроль без тринадцатого перехвата,
  18 комбинаций Master 0/125/250, начального 0/−345 сотых dB и COM
  S_OK/E_FAIL/E_ACCESSDENIED, а также повторный Run текущего fade;
- 12 ошибок установки: Protect, flush и восстановление прав каждой из
  четырёх страниц с проверкой полного отката.

Nonfade fixture исполняет реальные World::PlayMusic(false), LoadGraph,
QI/get_Volume и Run. Отрицательный контроль с прежними двенадцатью
перехватами воспроизводит начало Run при исходных 0 dB и Master=0.
Новый перехват отправляет mute до Run. Значение −345 в fixture означает
−3,45 dB, а не −345 dB. Master 0→250 восстанавливает исходную громкость
нового графа или текущий fade без изменения Music.

Эти проверки доказывают native control flow и ABI, но не измеряют звук
на настоящем устройстве. Если COM отклоняет put_Volume либо исходный
QI/Stop завершается ошибкой, native порядок Run/restore/Release
сохраняется; принудительных Stop, повторов и гарантий тишины при отказе
драйвера нет. Исправление рассчитано на штатный последовательный
музыкальный путь игры; произвольные вмешательства сторонних плагинов
и параллельные вызовы COM этим fixture не подтверждены.
